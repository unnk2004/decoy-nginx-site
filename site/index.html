PLATFORM
Three signals, checked everywhere, all the time.
Pulsewatch doesn't just ping a port. It watches the shape of your traffic over time and tells you when something is genuinely wrong — not when a single probe had a bad second.
Latency baselines
We learn the normal rhythm of every endpoint and alert on deviation, not on a fixed threshold that's wrong half the time.
15-second checks
Twelve check regions, fifteen-second intervals by default. Most outages are caught and paged before the first user notices.
Status pages that don't lie
Public status pages pull from the same data your on-call sees — no manual incident updates, no stale "investigating" banners.
Structured incident logs
Every alert comes with the request trail that triggered it, so the postmortem writes most of itself.
On-call routing
Escalation policies with overrides, quiet hours, and a second pass to backup contacts if the first page goes unacknowledged.
API-first
Every check, alert, and status page is scriptable. Most teams manage their monitors entirely from Terraform.
HOW IT WORKS
Set up in the time it takes to read this.
No agents to install on production. No sidecars. Point a check at a URL or a TCP port and Pulsewatch handles the rest.
01
Add an endpoint
Paste a URL, TCP port, or gRPC health check. Pick the regions you care about.
02
We learn its baseline
A few hours of checks build a latency and availability profile specific to that endpoint.
03
Route the alert
Slack, PagerDuty, webhook, or plain email — pick where deviations should land and for whom.
04
Watch it run
A live dashboard and a public status page, both reading from the same stream of checks.
